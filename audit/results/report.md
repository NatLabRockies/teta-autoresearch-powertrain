# Audit — reported vs deployable

Generated by `run_audit.py`. Every number here is produced outside both
experiment trees, on the full held-out set, from the models each arm actually
finished with.

- test rows: **327,647** of 1,638,466
- split: `harness.train_test_split(df, 0.2, seed=42)`, identical to both arms
- metrics: `harness.evaluate()`, identical to both arms

## 1. Reproduction check

Before anything else: does this harness reproduce what the arms reported? If
not, nothing below means anything.

| arm | metric | archived | reproduced | delta | tolerance |
| --- | --- | --- | --- | --- | --- |
| `unguided` | rmse | 0.004785 | 0.004795 | +0.20% | ±5.0% |
| `unguided` | trip_rmse | 0.001231 | 0.001235 | +0.32% | ±5.0% |
| `domain-guided` | rmse | 0.006823 | 0.006823 | -0.00% | ±2.0% |
| `domain-guided` | trip_rmse | 0.002239 | 0.002237 | -0.09% | ±2.0% |

**PASS** — both arms reproduce inside tolerance.

The tolerances differ on purpose. The domain-guided arm trains for a fixed 320
epochs and is deterministic on a given device, so it is held to ±2%. The
unguided arm's sequence member trains for a **wall-clock budget** rather than a
fixed number of updates, so a different host fits a different model; it gets
±5%. That is a reproducibility property of the arm, not of this audit, and it
is worth noting on its own: a result that depends on how fast the machine was
is a result that is hard to check.

## 2. The deployment contract

`contract.py` restates `domain.md` as a per-feature ledger. Six tiers, two of
them inside the contract:

| tier | meaning | in contract |
| --- | --- | --- |
| `LINK` | static link attribute or current-link average | yes |
| `LOOKBACK` | needs the single previously-traversed link | yes |
| `STATE` | causal, but needs more than one link of memory | no, on memory cost |
| `FUTURE` | needs links not yet traversed | no, on causality |
| `TRACE` | exists only in the simulated drive-cycle trace | no, on observability |
| `LABEL` | derived from the target of other links | no — there are no labels |

### `unguided` — 5 of 13 features deployable

| feature | tier | deployable | why |
| --- | --- | --- | --- |
| `speed_mph` | LINK | yes | link-average speed; posted or probe |
| `grade_percent` | LINK | yes | link-average gradient |
| `miles` | LINK | yes | link distance |
| `dke_per_mile` | FUTURE | **no** | (next_speed^2 - prev_speed^2) / miles. Spans the link from the PREVIOUS link's speed to the NEXT link's, so it inherits the next link — which is what the search is deciding. Its causal half is already in the model as dke_in_link. |
| `dke_in_link` | LOOKBACK | yes | (speed_mph^2 - prev_speed^2) / miles — kinetic-energy change from the entry speed to this link's own speed, from one link of lookback. This is the same physics the domain-guided arm reached as ke_delta_per_mile. |
| `gap_seconds` | TRACE | **no** | idle seconds between the previous link ending and this one starting, from link_start_time / link_end_time. Those columns are artifacts of the simulated drive-cycle trace; a map has no counterpart, so this is not recoverable at any memory price. The arm's own reasoning is sound — a stop means the entry speed was really 0 — but the signal is unobservable at inference. |
| `prev_miles` | LOOKBACK | yes | distance of the single previous link |
| `next_miles` | FUTURE | **no** | distance of the FOLLOWING link. Not chosen yet when the current link is scored; no amount of label state recovers it. |
| `next_gap_seconds` | TRACE | **no** | the exit-side mirror of gap_seconds. Fails twice over: it is trace-only AND it reads the following link. |
| `prev2_speed` | STATE | **no** | speed of the link TWO back. Causal — the vehicle has traversed it — but domain.md caps the lookback at one link, so this is one extra float every search label must carry, and labels differing in it cannot be merged. The one out-of-contract feature in this model that has an honest price. |
| `dv_out` | FUTURE | **no** | next_speed - speed_mph, the exit speed change. Inherits the next link. |
| `journey_rate` | LABEL | **no** | leave-one-out mean of the TARGET over the journey's training links, shrunk to the global mean. This is not a feature at inference: there are no labels to average, and the average spans links the search has not chosen. It is also the model's single largest lever. |
| `journey_gge_per_mile` | LABEL | **no** | the same journey offset weighted by distance — training energy_gge over training miles. Target-derived, journey-wide, same verdict. |

### `domain-guided` — 11 of 11 features deployable

| feature | tier | deployable | why |
| --- | --- | --- | --- |
| `speed_mph` | LINK | yes | link-average speed; posted or probe |
| `grade_percent` | LINK | yes | link-average gradient |
| `miles` | LINK | yes | link distance |
| `prev_speed_mph` | LOOKBACK | yes | speed of the single previously-traversed link |
| `ke_delta_per_mile` | LOOKBACK | yes | (speed_mph^2 - prev_speed_mph^2) / (2 * miles) — kinetic-energy change across the entry boundary, from one link of lookback |
| `sinuosity` | LINK | yes | travelled length over endpoint crow-flight distance; a static road attribute precomputed offline from geometry |
| `junction_turn_degrees` | LOOKBACK | yes | heading change from the previous link's exit bearing into this link's entry bearing; both bearings are static, the pairing needs one link of lookback |
| `prev_grade_percent` | LOOKBACK | yes | gradient of the single previous link |
| `prev_miles` | LOOKBACK | yes | distance of the single previous link |
| `prev_sinuosity` | LOOKBACK | yes | sinuosity of the single previous link |
| `vertices_per_mile` | LINK | yes | linestring vertex density; a static road attribute standing in for road class |

### Beyond the feature list

A feature ledger alone would pass two of the unguided model's three parts.
Both are outside the contract for reasons no column name reveals.

| component | tier | deployable | why |
| --- | --- | --- | --- |
| `sequence_member` | FUTURE | **no** | a 2-block dilated 1-D CNN over each journey's whole link chain. Kernel 5 at dilations 1 and 2 gives a receptive field of 13 links — SIX AHEAD as well as six behind. It reads the future structurally, not through a named feature, so no feature ledger catches it. A left-masked version of the same network IS causal, and this audit fits one to price the difference. |
| `journey_offset` | LABEL | **no** | a distance-weighted per-journey correction built from the training residuals of that journey's own links. Needs labels, and needs the whole journey. Not deployable in a route search at any price. |

## 3. Accuracy, reported vs audited

`rmse` is link-level GGE/mile; `trip_rmse` is trip-total GGE. Percentages are
against the shared baseline (0.013345 / 0.003037). Lower is better; negative percentages
are improvements over baseline.

| configuration | rmse | vs base | trip_rmse | vs base | what it is |
| --- | --- | --- | --- | --- | --- |
| `unguided/reported` | 0.004795 | -64.1% | 0.001235 | -59.3% | the full blend, 13 features, as the arm ran it |
| `unguided/as-run/gbdt-only` | 0.004962 | -62.8% | 0.001718 | -43.4% | tree ensemble alone; no sequence member, no journey offset |
| `unguided/as-run/no-offset` | 0.004803 | -64.0% | 0.001704 | -43.9% | trees + sequence member; no journey offset |
| `unguided/audited-mean` | 0.015628 | +17.1% | 0.004253 | +40.0% | as-trained trees; out-of-contract inputs absent (train mean) |
| `unguided/audited-contract` | 0.014050 | +5.3% | 0.004096 | +34.9% | as-trained trees; strict LINK+LOOKBACK substitution — the Compass number |
| `unguided/audited-state` | 0.011578 | -13.2% | 0.002726 | -10.2% | as-trained trees; prev2_speed restored (costs 1 float per search label) |
| `unguided/retrained-contract` | 0.007557 | -43.4% | 0.002362 | -22.2% | refit on LINK+LOOKBACK features only — the fair fight (5 features) |
| `unguided/retrained-state` | 0.007087 | -46.9% | 0.002246 | -26.1% | refit with prev2_speed allowed (6 features) |
| `unguided/retrained-causal-seq` | 0.007170 | -46.3% | 0.002279 | -24.9% | contract trees + left-masked CNN over 5 deployable features; no journey offset |
| `domain-guided/reported` | 0.006823 | -48.9% | 0.002237 | -26.3% | 11 features, as the arm ran it |
| `domain-guided/audited` | 0.006823 | -48.9% | 0.002237 | -26.3% | identical to reported: all 11 features are inside the contract |

### Reading it

- The domain-guided arm's reported and audited numbers are **identical** (0.006823 / 0.002237). It never left the contract, so
  there was nothing for the audit to take away.
- The unguided arm reported 0.004795 / 0.001235 and audits to **0.014050 / 0.004096** under the
  contract — +193% link and +232% trip against its own reported figure.
- Decomposing the blend, on the arm's own full feature set:
  the trees alone give 0.004962 / 0.001718; adding the sequence member moves that to 0.004803 / 0.001704 (-3.2% / -0.8%); adding
  the journey offset gives the reported 0.004795 / 0.001235 (-0.2% / -27.5%). Neither of those two additions is
  deployable — one reads ahead, the other reads labels.
- Refitting the unguided *recipe* inside the contract gives 0.007557 / 0.002362 — still behind the domain-guided
  model (+10.8% link, +5.6% trip). This is the fair fight: same
  constraints, same data, different research path.
- Buying one float of label memory for `prev2_speed` gives 0.007087 / 0.002246, a -6.2% / -4.9% move
  on the contract refit. That is the entire priced-memory option this
  model offers — unlike the previous pair of trees, whose journey features
  aggregated *observable* quantities and so had real causal substitutes,
  this arm's journey features are means of the target and have none.
- **Was the sequence model the value, or its view of the future?** A left-masked CNN — same architecture, same budget, reading only links
  already traversed — blended with the contract trees gives 0.007170 / 0.002279: -5.1% link and -3.5% trip against the contract refit.
  So a causal sequence member does carry real value, and a Compass
  implementation that can hold per-path hidden state could have it.
  But note what beats it: `retrained-state` (0.007087 / 0.002246) is better on both metrics for **one extra
  float per search label**. A single scalar of memory buys more than a
  whole causal sequence model does. If any of this is worth
  implementing, that is the cheap end to start from.

### Search-label state — the cost that decides feasibility

Compass merges search labels that describe the same state. Every extra scalar a
feature needs is a scalar the label must carry, and labels differing in it can
no longer be merged. This is the memory penalty `domain.md` names.

| model | extra floats per label | |
| --- | --- | --- |
| `domain-guided` | **0** | all 11 features derive from the current edge and the previous edge id, which the search label already carries |
| `unguided/as-run` | **not implementable** | not implementable at any memory cost. next_miles, next_gap_seconds and dv_out need links the search has not chosen; gap_seconds exists only in the simulated trace; journey_rate and journey_gge_per_mile are means of the target. The sequence member reads 6 links AHEAD as well as behind, and the journey offset needs labels. |
| `unguided/retrained-contract` | **0** | the 5 deployable features only (speed_mph, grade_percent, miles, dke_in_link, prev_miles) — same label cost as domain-guided |
| `unguided/retrained-state` | **1** | adds prev2_speed: one extra float per label, and labels differing only in the speed two links back can no longer be merged |

### The second objective

`domain.md` names inference cost as a competing objective, and on these
numbers it is the larger of the two effects. Even the *deployable* unguided refit is **657x** slower per link than the
domain-guided model — a million-traversal search goes from 1.4 s to 951 s.

That gap is a model-class choice, not a feature choice: 10,000 boosted
trees against two small networks. The domain-guided arm spent the last
third of its session halving its own inference cost, because `domain.md`
told it that mattered. The unguided arm optimised one metric and was
never told there was a second one, so it grew the ensemble instead. Both
behaved reasonably given what they were told; only one was told.
